The problem

Every company is deploying AI agents. Almost none can answer, on demand:

  • Who allowed this agent to do that?
  • How much did that agent spend last month?
  • Was any sensitive data sent to a third-party model?
  • Can we prove to an auditor what the agent did?

Vendors sell you an agent. Nobody sells you the governor.

What AXON is

AXON is the layer that sits around your agents — Claude Code, Codex, Cursor, Qwen, a local model, anything — and enforces three things no matter what:

Module What it does
🛡️ Shield Deny-by-default policy engine with three ready packs, and a checker that proves each pack refuses what it claims to.
📊 Observe Ed25519-signed, hash-chained audit ledger. Cost, denial, and integrity analytics.
🔐 Vault Secrets brokered as short-lived, single-use, policy-gated leases. Values never reach the ledger.
🔌 Core Model-agnostic runtime, RBAC, and a multi-agent orchestrator that keeps governance across delegation.

Quickstart

pip install -e ".[dev]"

# Run a governed task (offline mock by default)
axon run "read the changelog" --tool read_file=/sandbox/CHANGELOG.md --ledger ./audit.jsonl

# Verify the audit trail (supply the public key for strict verification)
axon keygen --key ./sign.key
axon audit --ledger ./audit.jsonl --pubkey ./sign.key.pub

# Check that each policy pack actually refuses what it claims to
axon shield

# Map compliance controls to the code and tests that implement them
axon compliance

# Open the governance dashboard over a real ledger
axon dashboard --ledger ./audit.jsonl --pubkey ./sign.key.pub

# Test a policy decision
axon policy-check tool.read_file --target /home/deploy/secrets/db.txt
# -> DENY  matched rule: deny *:tool.*->*secrets*

# List providers and prices
axon models

# See the full governance demo
python3 examples/demo.py

Real model providers

AXON is model-agnostic. Pick a provider by name, or let it auto-detect from the environment.

export AXON_ANTHROPIC_API_KEY=sk-ant-...        # Anthropic Messages API
export AXON_API_KEY=sk-...                      # OpenAI / Azure / Groq / Together
export AXON_BASE_URL=http://localhost:11434/v1  # Ollama / vLLM (no key needed)

axon run "summarise the incident" --provider anthropic --model claude-sonnet --budget 0.25
axon run "summarise the incident" --provider openai --model gpt-4o-mini
axon run "summarise the incident" --provider ollama --model llama3-local

from axon.providers import get_provider

provider = get_provider("anthropic")           # or "openai", "ollama", "vllm", "mock"
result = provider.complete("hello", model="claude-sonnet")
print(result.text, result.usage.cost_usd)

Every adapter speaks the vendor's real wire format over stdlib HTTP — no SDK lock-in, installable in air-gapped environments. Failures are typed (AuthError, RateLimitError, TransientError) with bounded exponential backoff; auth and 4xx errors are never retried.

Provider Auth env Notes
anthropic AXON_ANTHROPIC_API_KEY Native Messages API, anthropic-version pinned
openai AXON_API_KEY Any OpenAI-compatible endpoint
ollama / vllm none Local, keyless
mock none Deterministic, zero-cost — tests and demos

How the audit ledger works

record_hash = SHA256(prev_hash || canonical_json(record))
signature   = Ed25519(seq || record_hash)

Each record commits to the previous hash, so mutating or deleting any historical record breaks every subsequent hash. Hashing alone has a known limit: whoever holds the file can rewrite the whole chain and re-hash it consistently. Signing closes that gap, and verify(public_key=...) is fail-closed — when the auditor supplies a key, every record must carry a valid signature from it, so stripping signatures is detected rather than ignored. The Ed25519 implementation is pure Python (RFC 8032), verified against the RFC test vectors and cross-checked against cryptography. See axon/core/audit.py and axon/core/signing.py.

Security

AXON defends itself in depth. Seven layers, ordered by what an attacker reaches first: authentication, rate limiting, replay defence, security headers, injection detection, canary tokens, and self-verification.

axon token create --name operator --role operator --out tokens.yaml
axon canary honey-db --out canaries.txt
axon posture --tokens tokens.yaml --canaries canaries.txt   # per-layer status
axon scan --file untrusted-page.txt                         # injection check

The dashboard refuses to bind a non-loopback address without an authenticator. Tokens are stored as SHA-256 digests and compared in constant time; the plaintext is shown once and never persisted.

The honest premise, stated up front: no system is unbreakable. The goal is that a successful intrusion should be expensive, limited in scope, and detectable — not impossible. axon posture says so in its own output.

See docs/SECURITY-LAYERS.md for what each layer stops, what it does not stop, and the gaps that remain.

Status

v0.2.0 — governed runtime for single and multi-agent systems, with signed audit, RBAC, policy packs, secret brokering, an authenticated dashboard, a seven-layer security stack, framework adapters, and an executable compliance mapping. 246 tests.

Known limits, stated plainly: policy matching is glob-based rather than a full expression language; TLS termination and SSO/OIDC are the deployment's responsibility, not the dashboard's; the injection detector matches a known corpus of attack shapes and novel phrasings will get past it; EnvResolver is a local-development secret backend, not a production one; and the orchestrator executes delegations sequentially, so it is not yet a throughput play.

See CHANGELOG.md for what shipped and what is next.
